# PF-113 — Missing environment-probe contribution repair

Status: implementation and acceptance preparation; native qualification and release pending.

Issue [#113](https://github.com/techrote/ShadeDoomVK/issues/113) owns the reachable missing-probe PBR consumer repair. PF-020/#37 and SDVK-001 remain blocked until their separate gates pass. The [adopted contribution and sampling decision](PF-113-MISSING-IBL-DECISION.md) is implementation authority; [the original negative receipt](PF-113-ORIGINAL-NEGATIVE-VERIFICATION.json) preserves the exact accepted-master counterexample off GPU.

`lightmodel_pbr.glsl` now routes uniform and gathered environment samples through two helpers. Runtime pair0 returns zero before descriptor access or `base+1`; live pair selection, directions, coefficient order and roughness-dependent prefilter LOD remain. Irradiance uses explicit LOD0 on its one-mip cube, and both live accesses carry `nonuniformEXT`. No remaining-tap renormalization, substitute environment, BRDF/material recalibration or gameplay change is introduced.

The production-extracted CPU fixture protects the original producer, selector, guard and sampling bodies. Its sample/services logging distinguishes actual fixed 2D slots from allocator-backed cube pairs. The original fixture's incompatible accesses are never submitted to Vulkan. Current controls cover zero/all-zero/mixed taps, nonordinal live identities, original weights/order/directions/LOD, authored0, publication/reset, selector omissions and the dedicated sampler/view contracts. Strict compilation keeps assertions and warnings-as-errors enabled; compiled mutations must fail rather than merely match source text.

Measured preparation result: 17 focused tests passed under MSVC C++17 `/W4 /WX /UNDEBUG`; the current extracted fixture passed 323 source/service checks. The retained original still observed 20 incompatible attempts across 275 CPU checks and failed its require-safe mode as expected. These counts are CPU evidence, not actual Vulkan sampling or publication. The complete inherited suite and native gates remain required.

The native diagnostics are explicitly enabled with `-pf113observe <fresh-prefix>` and `pf113_probe_diag <fresh-prefix>`. The startup observer records actual immediate specialized PBR command emission, submitted surface-uniform bytes, bound pipeline/shader identity, creation metadata and normal completed-pass publication. It must observe the initial unavailable authored1 state, a real authored0/live-pair draw before publication and later live authored1 state without allocating diagnostic probe identities, forcing publication or changing probe selection. The fixture disables LevelMesh and ubershaders explicitly; this is not LevelMesh submission evidence.

Separate private fragment controls compile the actual packaged helpers and full `ProcessMaterialLight` body with observation-only exports. Real allocator-backed separated cube pairs, spatially varying cube texels, an R16_UINT map and float readbacks cover zero, mixed, live, differing live fragments across quad boundaries and roughness endpoints. Original sampling is compared only in a legal uniform live branch. Missing or varying original descriptor accesses are never launched. Normal command fences and retirement govern these private resources; fixed null/BRDF owners must remain unchanged.

Native acceptance requires a clean source-pinned RelWithDebInfo build, exact authored two-probe fixture without prebaked lumps, separate serialized core and synchronization validation, proved requested activation with zero errors/warnings, bounded normal process exits and unchanged source/build/input/layer identities. The runner independently validates SPIR-V and recomputes raw readbacks rather than trusting diagnostic PASS text. Presentation captures are scene context, not original/candidate parity or human approval.

No native PF-113 pass, GPU timing, frame-budget improvement, full bake robustness, human visual approval, P400 qualification or historical CFX/PF-017 acceptance is claimed by preparation. Raw game/palette/pixel content and unrestricted logs remain local; compact evidence publishes only counts, statuses and identities.
