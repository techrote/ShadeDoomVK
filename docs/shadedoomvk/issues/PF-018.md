# PF-018 — LevelMesh/AABB allocator and update-path performance

## Objective

Reduce CPU/memory churn in LevelMesh allocation/dirty-update and moving AABB paths after PF-004/PF-015 freeze correctness semantics, without changing rendered/query geometry or lighting/shadow results.

## Scope / required work

- Profile `MeshBufferAllocator` allocation/free/grow behavior, fragmentation, dirty-range merging/upload bytes and dynamic AABB update cost on representative dynamic scenes.
- Replace linear first-fit free-range scans with evidence-backed segregated bins/indexing or another compact structure while preserving exact allocation ownership and PF-004 debug validation.
- Replace overly aggressive growth behavior with an evidence-backed bounded/geometric policy that reduces peak unused capacity without increasing pathological realloc/upload stalls.
- Preserve stable allocated ranges where callers require them; do not compact/move live ranges unless all references/generations are explicitly updated and equivalence proven.
- Cache or precompute dynamic AABB leaf→parent update topology so moving polyobject lines do not recursively rediscover the same node path each change when topology is unchanged.
- Optimize dirty upload range merging/copy batching only where it preserves byte-for-byte destination state.
- Instrument allocator searches, fragmentation/used/total capacity, grow events, dirty range count/bytes, AABB path traversals and update time.

## Non-goals

- No LevelMesh ownership/invalidation redesign (PF-004 already owns it).
- No visibility/shadow semantic change (PF-015).
- No geometry simplification, culling, precision reduction or image-quality tradeoff.
- No general scene graph rewrite.

## Dependencies

PF-004, PF-015.

## Concurrency guidance

May overlap PF-017 when files are distinct; coordinate if light-list allocation shares `MeshBufferAllocator`. PF-019 depends on this issue. Do not overlap PF-004 implementation.

## Required context

Read `AGENTS.md`, PF dependency evidence, `rag/03-LEVELMESH-MUTATION-MATRIX.md`, identity/lighting RAG, current LevelMesh allocator/upload/AABB source and canonical body.

## Autonomous implementation prompt

Complete PF-018 autonomously. Measure the accepted PF allocator/update paths first; introduce only output-equivalent allocator/growth/AABB/upload optimizations; preserve all ownership/generation invariants; benchmark and stress fragmentation/dynamic geometry. Dedicated branch → tests/benchmarks/docs → PR → required checks → merge → verify `master` → RAG/ledger → close.

## Acceptance criteria

- Qualified allocation workloads perform fewer/cheaper free-range searches and/or use materially less wasted capacity with no invalid range reuse.
- Growth policy is bounded/documented and avoids regressions on large allocations.
- Dynamic AABB updates avoid repeated full recursive parent-path discovery where topology is stable, with identical trace results.
- Dirty upload optimization, if adopted, produces identical GPU buffer contents for fixtures.
- Representative workload shows measured CPU/memory improvement and PF image/query/state equivalence.
- Required CI passes; PR merged and verified.

## Verification

Fragmentation allocate/free/reuse stress; dynamic polyobject motion and ray/visibility trace comparison; buffer snapshot/range checks; large growth workloads; before/after CPU/memory/upload counters; PF equivalence.

## Expected artifacts

Allocator/growth optimization; AABB parent-path cache/index; optional dirty-range batching improvements; stress tests/benchmarks; LevelMesh RAG/ledger updates.

## Blocking / stopping conditions

Do not compact/move live ranges or change trace geometry merely for speed unless full identity/reference updating is demonstrably safe. Reject an optimization that improves microbenchmarks but increases real-scene peak memory/stalls or changes query results.
