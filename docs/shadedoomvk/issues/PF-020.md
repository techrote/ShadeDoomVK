# PF-020 — Pre-foundation hardening synthesis and SDVK-001 release gate

Status: **DEPENDENCY-READY after PF-019 tracker closure.** PF-001..PF-019 implementation/evidence is accepted, and CFX-000 / #75 is complete. PF-020 has no remaining external PF/CFX prerequisite; its own fail-closed synthesis may still identify a blocker.

## Objective

Consume all PF-001..PF-019 evidence and decide, fail-closed, whether the inherited/refactored renderer ground is trustworthy enough to begin SDVK-001 and the founding visual-feature programme.

## Scope / required work

- Inspect current `master`, every PF issue/PR/evidence artifact, complete relevant open/closed issue set and the full canonical/RAG corpus.
- Build a PF evidence matrix mapping each PF requirement, confirmed baseline defect, refactor invariant and performance-equivalence claim to merged code/tests/results.
- Rerun the complete applicable PF oracle from clean state, including resource lifetime/reuse, LevelMesh mutations, materials, lighting/occlusion, probes/lightmaps, portals/views, shadows and no-quality performance regressions.
- Verify every confirmed source defect assigned to PF is fixed or has explicit evidence that a superseding accepted refactor makes the bad state impossible.
- Verify no stale/mismatched renderer identity appears under repeated level/resource stress.
- Verify output/state-equivalent PF refactors/optimizations remain within declared tolerance and did not silently change quality policy.
- Reconcile every `docs/shadedoomvk/rag/*.md` document against the resulting source; resolve or record any disagreement.
- Review performance results for regressions masked by isolated microbench wins.
- Create `docs/shadedoomvk/PF-FREEZE-MANIFEST.md` naming exact merge commit, accepted PF issues/PRs, test commands/results, key before/after metrics, known limitations and explicit gate status.
- Update `10-EXECUTION-LEDGER.md`, roadmap/graph/traps/provenance as needed.
- If and only if the gate passes, record **SDVK-001: UNBLOCKED**. Do not implement SDVK-001 in this issue.

## Non-goals

- Do not implement ShadeDoomVK rebranding/build foundation work from SDVK-001.
- Do not add new renderer features to make the freeze look better.
- Do not waive failing PF criteria by relabeling defects as future polish.
- Do not require optional future aspirations such as POM, sprite shadow cards, clustered lighting or temporal effects.

## Acceptance criteria

- Every PF issue/result is traceable from the evidence matrix to merged code/tests/artifacts.
- All confirmed PF source defects are fixed or demonstrably superseded.
- No unresolved stale renderer identity, raster/query divergence, wrong light/probe/shadow selection or unsafe reservation behavior remains in PF-declared supported paths.
- PF refactors/performance changes satisfy output/state-equivalence contracts and retain measured benefits without hidden quality changes.
- Portal/mirror/camera/probe contexts remain correctly separated.
- Full applicable PF test suite/required CI passes from final `master` state.
- All RAG/canonical docs match implementation.
- Freeze manifest names known limitations honestly.
- `SDVK-001: UNBLOCKED` is recorded only if all gate criteria pass.

## Verification

Run the complete PF oracle plus dependency-specific stress/benchmark subsets from clean state; verify merge SHAs and issue closure evidence; compare source/RAG symbols; search for unresolved PF/TODO/trap entries; inspect final issue graph for blocks; record exact commands/results in the freeze manifest.

## Expected artifacts

`PF-FREEZE-MANIFEST.md`; PF evidence matrix; final test/benchmark report; reconciled RAG/planning/ledger; explicit SDVK-001 gate status; synthesis PR/merge if successful.

## Blocking / stopping conditions

Any unresolved condition capable of stale/corrupt renderer identity, inconsistent query/render geometry, materially wrong light/probe/shadow state, unsafe capability/resource fallback, silent compatibility regression, or PF performance quality tradeoff blocks release. Record named blockers and affected dependents; do not merge a passing freeze manifest or unblock SDVK-001 while such a condition remains.
