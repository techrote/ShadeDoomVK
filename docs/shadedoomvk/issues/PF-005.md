# PF-005 — Asynchronous texture jobs and persistent staging-upload arena

## Objective

Make asynchronous texture preparation/upload lifetime-safe and reduce per-texture Vulkan staging allocation/wait churn without changing produced texture content, filtering, mip policy or visible quality.

## Scope / required work

- Audit `VkTextureManager` worker/main queues, `CreateUploadID`/`CheckUploadID`, texture destruction/reset and upload completion paths.
- Replace or wrap raw upload-ID/target assumptions with PF-002 generation-aware job validity so destroyed/recreated targets cannot receive stale completions.
- Implement a persistent staging ring/arena/pool, or a measured equivalent, to avoid one Vulkan staging allocation per ordinary texture upload.
- Define bounded reuse/fence/retirement behavior and preserve transfer ordering/layout transitions.
- Reduce the current coarse deferred-upload wait cliff where possible without unbounded staging memory growth.
- Preserve worker exception propagation to the main thread and clean shutdown/cancellation behavior.
- Instrument queued jobs, cancelled/stale jobs, staging bytes/high-water/reuse and transfer waits/stalls.
- Benchmark representative burst and ordinary precache/upload workloads using PF-001 equivalence evidence.

## Non-goals

- No texture streaming/virtual texturing system.
- No new texture-compression, mip, filtering or quality policy.
- No asynchronous gameplay/resource-loading semantic changes beyond renderer texture preparation already supported.
- No descriptor lifetime redesign beyond consuming PF-002/PF-003 contracts.

## Acceptance criteria

- A queued completion targeting a destroyed/recreated texture is rejected safely and deterministically.
- Ordinary/burst uploads reuse staging memory rather than allocating a dedicated Vulkan staging buffer for every image in the qualified path.
- Bounded staging retirement/fence behavior is documented and cannot overwrite in-flight data.
- Uploaded image contents/mips/material-visible results match PF baseline for equivalent settings.
- Upload allocation/wait/stall counters show a measured improvement on at least one representative workload without regression on ordinary workloads beyond declared noise/tolerance.
- Shutdown/error propagation remains correct.
- Required CI passes; PR merged and verified.

## Verification

Exercise repeated create/destroy while async work is queued, large texture burst/precache, translated/indexed and ordinary truecolor textures, shutdown with queued work, and PF image/state equivalence. Record staging allocation count, bytes/high-water, wait count/time and stale-job rejection.

## Expected artifacts

Generation-safe texture job implementation; reusable staging arena/pool; stress tests; benchmark/equivalence evidence; updated identity/Vulkan RAG; PF ledger entry.

## Blocking / stopping conditions

Stop if staging reuse requires changing texture data/mip/filter policy, if safe fence/lifetime ownership cannot be proven, or if the proposed arena increases peak memory/stalls without measured benefit. Preserve the old path or narrow scope rather than claiming a speculative optimization.

## Implementation contract and evidence

The implementation is defined by `PF-005-TEXTURE-UPLOAD-CONTRACT.md` and the compiled `texture_upload_contract_fixture.cpp`.

- async hardware-texture jobs capture both the PF-002 owner epoch and a generation-aware target identity;
- reset/recreation, target retirement, owner shutdown and pointer-address reuse reject stale completions;
- upload job-ID wrap is explicit and collision-safe rather than relying on signed integer overflow;
- the qualified path uses one lazily-created, bounded 64 MiB CPU-visible transfer-source arena with aligned non-overlapping slices;
- arena storage is reused only after the existing upload-only completion wait returns; oversized uploads retain the inherited dedicated-buffer fallback;
- the deterministic burst fixture models 1,024 × 64 KiB uploads and reduces the qualified-path staging-buffer allocation model from 1,024 Vulkan buffers to one persistent backing buffer while bounding high-water and reset count;
- texture content processing, image formats, mip generation, sampler/filter policy, layout transitions, gameplay, audio and provenance semantics remain outside the changed contract.

PF-001 CI has no runnable IWAD/GPU image harness, so the implementation does not invent runtime image/timing evidence. Equivalence is guarded by unchanged texture-semantic code, the deterministic source/contract oracle, the compiled adversarial fixture and the full inherited platform build matrix. See `PF-005-TEXTURE-UPLOAD-CONTRACT.md` for the exact evidence boundary.
