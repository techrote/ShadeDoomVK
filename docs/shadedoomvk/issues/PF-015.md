# PF-015 — Shadow/visibility cache correctness repair pack

## Objective

Repair baseline shadow-light cap selection and actor/static-light visibility-cache invalidation so lighting/shadow results remain correct and deterministic when dense light sets or moving world occluders are present.

## Scope / required work

- Preserve/reproduce the current 1024-shadow-light traversal-order behavior in `hw_entrypoint.cpp`.
- Define and implement deterministic, spatially meaningful selection when more active shadowmapped lights exist than slots. Prefer lights relevant to the active render view/scene using an evidence-backed metric; document ties/stability and context handling.
- Preserve baseline behavior when active shadowmapped lights fit within capacity.
- Reproduce stationary actor+light with a moving LevelMesh/polyobject/sector occluder where cached actor-light visibility can become stale.
- Integrate an appropriate PF-004 world/query visibility generation/epoch into the cache key/invalidation path.
- Ensure portal/view context from PF-010 participates where cached visibility is context-dependent.
- Add diagnostics for cache hits/misses/invalidation reasons and shadow candidates/selected slots.
- Preserve ray-query-disabled/world-shadow fallbacks.

## Non-goals

- Do not reduce shadow resolution/quality or number of slots as an optimization.
- Do not add new sprite-cast shadow architecture; SDVK-012/013 own that.
- Do not redesign all shadow filtering/softness.
- Do not optimize actor light gathering yet; PF-016 consumes the corrected visibility semantics.

## Dependencies

PF-004, PF-010, PF-011.

## Concurrency guidance

May overlap PF-012/PF-013/PF-014 with careful file ownership. PF-016/PF-018 depend on it and must not proceed against old cache/selection semantics.

## Required context

Read `AGENTS.md`, PF dependency evidence, `rag/03-LEVELMESH-MUTATION-MATRIX.md`, `rag/05-LIGHTING-SHADOW-TRUTH-TABLE.md`, `rag/07-PORTAL-COORDINATE-SPACES.md`, known traps and current shadow/actor visibility code.

## Autonomous implementation prompt

Complete PF-015 autonomously. Build failing dense-shadow and moving-occluder fixtures first. Define deterministic cap policy and cache validity using accepted LevelMesh/view generations; repair the defects without reducing quality; add diagnostics and preserve fallbacks. Dedicated branch → tests/evidence/docs → PR → required checks → merge → verify `master` → RAG/ledger → close only after both defect classes are accepted.

## Acceptance criteria

- Shadow-slot assignment under >1024 candidates is deterministic and based on documented view/scene relevance rather than linked-list accident.
- With <=1024 eligible lights, selected shadowmapped set remains baseline-equivalent.
- Moving relevant world occlusion invalidates actor/static-light visibility even when actor/light positions are unchanged.
- Cache validity includes necessary LevelMesh and view/portal generation/context state without disabling caching globally.
- Diagnostics expose candidate/selected counts and invalidation reasons.
- Optional ray-query/shadow fallbacks remain valid.
- Required CI passes; PR merged and verified.

## Verification

Dense light fixtures below/at/above cap with reordered creation/list order; camera/view movement where cap relevance changes; moving polyobject/sector occluder with stationary actor/light; portal-group cases; cache hit/miss metrics; PF image/state equivalence outside corrected cases.

## Expected artifacts

Deterministic cap selection; world/context-aware visibility cache invalidation; regression fixtures/diagnostics; updated lighting/LevelMesh/portal/trap RAG; evidence/ledger entry.

## Blocking / stopping conditions

Stop if no relevance metric can be defined without a product-level visible-quality decision; preserve deterministic baseline-compatible fallback and record the decision blocker. Do not solve cache staleness by disabling all caching unless evidence proves no viable keyed invalidation exists.
