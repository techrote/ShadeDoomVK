# PF-015 — Shadow/visibility cache correctness repair pack

## Objective

Repair baseline shadow-light cap selection and actor/static-light visibility-cache invalidation so lighting/shadow results remain correct and deterministic when dense light sets or moving world occluders are present.

## Implemented repair contract

PF-015 now has an explicit implementation contract at `docs/shadedoomvk/PF-015-SHADOW-VISIBILITY-CONTRACT.md`.

- Shadow-map capacity remains 1024 rows. Eligible sets at or below capacity preserve inherited linked-list order and row identity exactly.
- Overflow is selected by squared distance to the interpolated central main render viewpoint, then deterministic spatial/light semantic tie fields. Linked-list order no longer decides which non-equivalent lights survive the cap.
- `stat shadowmap` exposes processed/candidate/selected/dropped counts.
- Actor/static-light cache validity now includes PF-004 `LevelMeshMutationEpochs::Query` and stable portal-group context in addition to inherited actor/light invalidation. Moving world occluders therefore invalidate stationary actor/light results without disabling caching globally.
- Sun visibility rejects stale PF-004 query epochs as well.
- PF-010 transient render `epoch`/`identity` are deliberately excluded because they change every pass and are not inputs to the LevelMesh world trace. Stable portal-group displacement is the context key that participates in the current trace semantics.
- `stat actorlightcache` exposes hits/misses and actor/world/portal/light invalidation reasons.

Adversarial coverage includes below/at/above 1024, reversed candidate traversal, view movement, equal-distance ties, stationary actor/light with changed world query epoch, portal-group changes and explicit actor/light invalidators.

## Scope / required work

- Preserve/reproduce the current 1024-shadow-light traversal-order behavior in `hw_entrypoint.cpp`.
- Define and implement deterministic, spatially meaningful selection when more active shadowmapped lights exist than slots. Prefer lights relevant to the active render view/scene using an evidence-backed metric; document ties/stability and context handling.
- Preserve baseline behavior when active shadowmapped lights fit within capacity.
- Reproduce stationary actor+light with a moving LevelMesh/polyobject/sector occluder where cached actor-light visibility can become stale.
- Integrate an appropriate PF-004 world/query visibility generation/epoch into the cache key/invalidation path.
- Ensure portal/view context from PF-010 participates where cached visibility is context-dependent.
- Add diagnostics for cache hits/misses/invalidation reasons and shadow candidates/selected slots.
- Preserve ray-query-disabled/world-shadow fallbacks.

## Non-goals

- Do not reduce shadow resolution/quality or number of slots as an optimization.
- Do not add new sprite-cast shadow architecture; SDVK-012/013 own that.
- Do not redesign all shadow filtering/softness.
- Do not optimize actor light gathering yet; PF-016 consumes the corrected visibility semantics.

- Diagnostics expose candidate/selected counts and invalidation reasons.
- Optional ray-query/shadow fallbacks remain valid.
