# PF-017 — Light/material data-path performance

## Objective

Reduce measurable CPU/upload overhead in dynamic-light preparation and material descriptor lookup **only where a candidate produces a representative physical performance benefit**, while preserving selected lights, ordering/classes, texture bindings, sampler choices, material-state distinctions and rendered output.

PF-017 is an optimization/qualification task, not a mandate to deploy a predetermined representation. A measured no-go for an investigated optimization class is an acceptable outcome when the existing path is faster or the candidate cannot be proven safe.

## Scope / required work

### Dynamic lights

- Profile `VkRenderState::UploadLights`, `LightBufferSSO` construction/usage and repeated `FDynLightInfo` packing/upload after PF-016.
- Investigate reductions in repeated preparation/upload work, including source-owned temporal reuse, physical deduplication or another representation **only when measurement justifies it**.
- Preserve exact per-consumer logical light sets, normal/subtractive/additive classes, ordering and shader-visible packed state.
- Any retained reuse mechanism must have an explicit safe fallback when identity, lifetime or mutation state is ambiguous.
- For the promising source-owned temporal-reuse prototype, finish the source-ID/lifetime/adversarial acceptance work before retention.

### Material lookup

- Profile `VkMaterial::GetDescriptorEntry` using representative real workloads and the accepted post-PF-013 material state.
- Treat the current linear scan as the accepted baseline.
- Alternative canonical lookup structures may be tested, but retain them **only if they demonstrate a physical or otherwise clearly material measured benefit without semantic regression**.
- A documented no-go for hashing/indexing satisfies this investigation when representative evidence shows the accepted linear path is faster or the total lookup cost is immaterial.
- Preserve all accepted clamp/translation/global-shader/palette/indexed-state distinctions and exact returned bindless ranges.

### Default/placeholder resources

- Descriptor/default-resource sharing is optional.
- Attempt it only where equivalence is provable, PF-003 generation/lifetime semantics remain correct, and there is a useful measured reduction in descriptor/resource work.
- A documented no-go or “not worthwhile” disposition is acceptable.

### Instrumentation

Record enough evidence to distinguish useful work from attractive-but-slower reductions: logical/reference counts, mapped/upload bytes, cache populations/probes, lookup time, setup/frame timing, fallback counts, oracle mismatches and any descriptor/resource savings.

## Non-goals

- No selected-light culling or light-count reduction.
- No light math, quality or class change.
- No semantic material feature change.
- No descriptor-capacity redesign.
- No requirement to introduce hashed material lookup.
- No requirement to physically deduplicate light records if another safe representation performs better.
- No requirement to retain an optimization merely because it reduces bytes, probes or allocations when end-to-end timing regresses.

## Measured evidence already established — 2026-09-24

### Rejected frame-local light deduplication/indirection

The accepted baseline copied 3,971,280 light-buffer bytes in the dense workload: 49,473 logical records with 217 distinct packed states.

A frame-local hash/indirection prototype reduced mapped writes by **94.24%**, but regressed median `S: Setup` from **3.615 ms to 8.432 ms (+133.25%)** across five alternating physical GTX 1650 SUPER pairs; every pair regressed. It is rejected and must not be revived without materially new evidence.

### Promising source-owned temporal light reuse

The second light prototype retains the original physical shader-visible record layout and avoids the first prototype's per-reference hashing/indirection.

Observed evidence:

- mapped writes reduced **13.83%**;
- median `S: Setup` improved **3.660 ms → 3.410 ms (-6.83%)**;
- every one of five alternating physical pairs improved;
- all five full images matched exactly;
- dense and moving checkpoint buffers matched;
- direct packing oracle recorded zero mismatches.

This remains the current implementation direction. PR #74 has now completed the source-ID/lifetime/adversarial work and cross-platform off-GPU CI; it is **not yet accepted** because final-source physical GTX 1650 SUPER A/B performance and image/state confirmation remain pending.

### Material lookup no-go

Published Champions workloads reached 15 variants/material, 17 with the all-champions setting.

Measured canonical alternatives both regressed against the accepted linear oracle:

- node hash: **+94.8%** median lookup cost;
- flat/open-addressed hash: **+36.8%**;
- every measured pair regressed;
- observed lookup results matched the linear oracle.

A later Sunlust MAP30 + Champions workload sustained a median **1,201 lookups/frame into caches above eight entries**, but estimated large-cache search cost was only about **47.13 μs/frame**. A previous-hit shortcut increased large-population comparisons by **1.81%**.

Therefore PF-017 records **NO-GO for replacing the accepted linear material lookup on current evidence**. No further search for increasingly pathological content is required merely to manufacture a hashing win. Reconsider only if future ordinary/representative content demonstrates materially different lookup populations/cost.

## Acceptance criteria

PF-017 is accepted when all of the following are true:

- **Semantic invariance:** every consumer sees the same logical ordered light set/classes and the same shader-visible packed state as the accepted baseline for the exercised contract.
- **Light-path disposition:** either:
  - a retained light-preparation/upload optimization demonstrates repeatable representative physical benefit and passes the required identity/lifetime/adversarial gates; **or**
  - the investigated candidates are restored/rejected with sufficient measured evidence to establish a documented no-go.
- **Material-path disposition:** representative real-workload profiling is complete; the accepted linear path may remain unchanged when alternatives do not demonstrate benefit. The existing hash/index evidence satisfies this criterion unless materially new evidence appears.
- **Material correctness:** any retained material-path change returns exactly the accepted bindless range for equivalent post-PF-013 state and distinguishes every state that must remain distinct.
- **Default-resource sharing:** optional; if retained it must be PF-003 generation-safe, shader-semantically identical and measurably useful. Otherwise an explicit no-go/not-worthwhile disposition is sufficient.
- **Output/state equivalence:** retained renderer changes pass the required PF image/state/oracle fixtures with no quality-policy change.
- **Performance discipline:** no candidate is accepted solely because it reduces bytes, probes, allocations or logical work; representative end-to-end timing must not materially regress.
- **Integration:** required CI passes on the exact final head; PR is merged; resulting `master` is verified; RAG/ledger/canonical PF-017 record are reconciled.

## Verification

For any retained light optimization:

- pre/post per-consumer source IDs where observable, order and classes;
- packed shader-visible records/ranges;
- mutation/revision transitions;
- duplicate-source cases;
- class changes;
- ambiguous-identity fallback;
- reset/destruction/recreation and reuse/wrap boundaries;
- portal/nested-context coverage where the ownership path can reach them;
- mapped/upload byte counters and fallback counts;
- packing/state oracle;
- representative alternating physical A/B timing;
- full image/state equivalence.

For material lookup:

- preserve the existing real-workload population/probe/timing evidence and linear-oracle results;
- do not rerun alternative lookup design work unless new representative evidence establishes enough cost to justify it;
- if such evidence appears, cover translations, clamps, global shader state, palette/indexed interpretation, reset/reuse and deliberate collision/equality boundaries.

## Expected artifacts

- Final source-owned temporal light-reuse implementation **if** it survives the remaining gates, otherwise a documented light-path no-go.
- Material lookup profiling/no-go record retaining the accepted linear implementation unless new evidence justifies change.
- Optional default-resource optimization only if safe and useful.
- Focused tests/oracles/benchmarks/diagnostics for retained code.
- Exact physical performance/equivalence evidence for the final renderer head.
- Reconciled PF-017 RAG, issue record and execution ledger.

## Blocking / stopping conditions

- If light source identity, mutation state, class, ordering or required lifetime cannot be proven safe, fall back to the accepted packing/upload path and record the no-go.
- If a light candidate loses its representative physical benefit, do not retain it merely for byte reduction.
- If a material lookup candidate is slower than the accepted linear path, or the total representative lookup cost is too small to justify added complexity, retain linear lookup and consider that investigation complete.
- If a descriptor/material key aliases previously distinct accepted state, reject it.
- Do not keep PF-017 open indefinitely to search for a workload that validates a predetermined optimization.
- Do not begin PF-019 implementation until PF-017 has a complete accepted implementation or documented no-go disposition and the final issue/RAG/ledger state is reconciled.
