# PF-008 — Existing material-layer semantic refactor

## Objective

Make the inherited material-layer model explicitly semantic for its existing channels without changing existing material authoring, shader selection, per-layer sampling, palette/translation behavior or visible output.

## Scope / required work

- Audit `FMaterial`, `FMaterialLayers`, `MaterialLayerInfo`, GLDEFS/custom-shader parsing, shader defines/layer bindings and `VkMaterial` descriptor construction.
- Introduce semantic identifiers/metadata for currently supported channels: base/albedo, normal, legacy specular, metallic, roughness, AO, bright/emissive, detail, glow and custom extension layers.
- Preserve inherited `MaterialLayerSampling` behavior and sampler overrides; remove or contain brittle positional assumptions where doing so is behavior-equivalent.
- Make semantic→binding/order translation explicit so legacy shaders can retain their expected texture layout while later ShadeDoomVK code can reason by semantic name.
- Preserve placeholder/default texture behavior or replace it only with a provably equivalent default-resource mechanism.
- Add diagnostics/tests showing semantic, binding, sampler and source texture for representative material variants.
- Integrate PF-003 descriptor lifetime/reservation rules.

## Non-goals

- Do not add a user-visible height map or POM; SDVK-005/008 own those features.
- Do not change normal-map tangent-space math; SDVK-007 owns explicit sprite TBN.
- Do not recalibrate PBR lighting; PF-011/SDVK later work owns lighting policy.
- Do not break existing GLDEFS/custom shader authoring.

## Dependencies

PF-003.

## Concurrency guidance

May overlap PF-004/PF-006/PF-007/PF-009/PF-011 where file ownership permits. PF-013/PF-017 depend on the accepted semantic model. Avoid concurrent PF-003 changes to descriptor/layer binding files until rebased.

## Required context

Read `AGENTS.md`, `04-DONOR-PROVENANCE.md`, `rag/04-MATERIAL-SHADER-CONTRACT.md`, PF-001/PF-003 evidence and current material/shader code.

## Autonomous implementation prompt

Complete PF-008 autonomously. Treat per-layer sampling as inherited functionality, not a feature to port. Introduce semantic metadata/translation around existing channels, preserve legacy binding/output behavior, add diagnostics/equivalence tests, update RAG, then branch→PR→checks→merge→verify→ledger→close.

## Acceptance criteria

- Existing material channels have explicit semantic identity accessible to renderer code/diagnostics.
- Existing legacy, specular, PBR, bright/detail/glow, custom, palette and translated paths bind equivalent textures/samplers/shaders.
- No existing material syntax is deliberately broken.
- No height/POM feature is exposed prematurely.
- PF image/state equivalence passes for representative material variants.
- Required CI passes; PR merged and verified.

## Verification

Compare old/new layer sequence, descriptor texture indices, sampler choices, shader keys and images for albedo-only, legacy normal+specular, PBR, bright/detail/glow, custom layers, translated/indexed and warped/canvas exclusions.

## Expected artifacts

Semantic material representation/translation; diagnostic dump/tests; updated material RAG/donor note if needed; PF evidence/ledger entry.

## Blocking / stopping conditions

Stop if semantic tagging cannot be made one-to-one with existing shader bindings or if a proposed cleanup changes legacy/custom material behavior. Preserve positional compatibility behind an explicit adapter rather than forcing a new authoring model.
