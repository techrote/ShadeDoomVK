# PF-004 — LevelMesh ownership, mutation and allocator hardening

## Objective

Make LevelMesh ownership, mutation, dirty-domain and invalidation behavior explicit and defensively checked so raster geometry, renderer query geometry, GPU buffers, lightmap/probe state and acceleration structures cannot silently diverge as later ShadeDoomVK work becomes more dynamic.

## Scope / required work

- Audit `LevelMesh`, `DoomLevelMesh`, `VkLevelMesh` and the Doom mutation callbacks that feed them.
- Reconcile actual behavior with `rag/03-LEVELMESH-MUTATION-MATRIX.md`; correct the document where source evidence disproves an assumption.
- Define a compact set of owned mutation/dirty domains and explicit generation/epoch changes for geometry, surface/material state, light state, light lists, query/collision state, portal state and lightmap/probe dependencies.
- Reuse/refine existing `SurfaceUpdateType`, callback and `MeshBufferUploads` mechanisms rather than introducing a parallel invalidation universe.
- Add defensive allocator checks in debug/test paths for invalid ranges, overlap/double-free and stale-generation access where PF-002 applies.
- Make CPU query/collision and Vulkan BLAS/TLAS update/rebuild responsibilities explicit for geometry mutations.
- Make lightmap/probe invalidation requirements explicit when atlas/layout/geometry dependencies change.
- Add PF fixtures covering representative floor/ceiling, side, polyobject, light-list, portal and resource-reset mutations.

## Non-goals

- Do not perform allocator/free-bin/growth performance redesign; PF-018 owns that after the contract is stable.
- Do not redesign Doom gameplay geometry or portal semantics.
- Do not replace LevelMesh with an object graph or scene graph.
- Do not intentionally change rendered output except to reject/detect invalid stale state in debug/test paths.

## Dependencies

PF-002.

## Autonomous implementation prompt

Complete PF-004 autonomously from current `master`. Map actual LevelMesh ownership/invalidation first, then implement the smallest explicit mutation/dirty/generation contract that prevents renderer-query/GPU/lightmap/probe divergence. Preserve current valid output. Add defensive tests and update RAG. Work on a dedicated branch; open a PR; repair required CI; merge only after checks pass; verify `master`; update ledger; close only when criteria hold.

## Acceptance criteria

- Major LevelMesh-owned state domains and their invalidation triggers are explicit in code/docs/diagnostics.
- Representative geometry mutations update both rendered and renderer-query/occlusion state consistently.
- Debug/test fixtures detect invalid range reuse, overlap/double-free or stale-generation use rather than silently accepting it.
- BLAS/TLAS and CPU fallback responsibilities are explicit and tested for at least one dynamic geometry case.
- Lightmap/probe invalidation requirements are inspectable for relevant geometry/atlas changes.
- No deliberate valid-scene output change.
- Required CI passes; PR merged and verified on `master`.

## Verification

Run PF mutation fixtures for floor/ceiling height, side update, dynamic/polyobject motion, light-list change, portal-related update and level/resource reset; compare rendered/query state; run allocation/free stress under debug assertions; verify PF image/state equivalence.

## Expected artifacts

- explicit LevelMesh mutation/invalidation implementation and diagnostics;
- defensive allocator/lifetime assertions/tests;
- mutation fixtures;
- updated `rag/03-LEVELMESH-MUTATION-MATRIX.md` and identity RAG where needed;
- PF evidence/ledger entry.

## Blocking / stopping conditions

Stop if a proposed ownership refactor requires rewriting Doom gameplay geometry/portal semantics, if an invalidation trigger cannot be made precise without a larger prerequisite, or if raster/query equivalence cannot be demonstrated. Record/block dependent PF issues rather than hiding uncertainty behind full-refresh calls everywhere.
