# PF-002 — Renderer resource generations, stale-reference detection and lifetime contract

## Objective

Introduce a lightweight, explicit lifetime/generation contract for recyclable renderer identities so stale resource references can be detected and invalidated before richer ShadeDoomVK features increase index reuse pressure.

## Scope / required work

- Inventory renderer-owned recyclable identities that can outlive the object that created them: bindless slots/ranges, lightmap/probe resource indices, relevant LevelMesh allocation identities/epochs, async upload targets and renderer-reset epochs.
- Define the smallest common generation/epoch model that can validate long-lived references without converting hot renderer data into heavyweight heap objects.
- Add debug/diagnostic stale-reference detection and counters to PF-001's oracle.
- Establish explicit reset/invalidation events for level unload/reload, material/texture destruction, lightmap/probe reset and renderer/device-resource reset.
- Provide integration hooks consumed by PF-003/PF-004/PF-005 rather than implementing all subsystem-specific policies here.
- Document which existing raw indices remain intentionally frame-local or owner-scoped and therefore do not need generation wrappers.

## Non-goals

- Do not choose bindless capacity/reservation policy (PF-003).
- Do not redesign LevelMesh allocation/update structures (PF-004).
- Do not replace Vulkan handles or game semantic IDs with a universal generic handle system.
- Do not add user-visible rendering features or change accepted output.

## Dependencies

PF-001 accepted and merged.

## Concurrency guidance

May proceed in parallel with PF-006, PF-007, PF-009 and PF-011. PF-003/PF-004/PF-005 must consume the accepted lifetime contract. Avoid parallel conflicting edits to descriptor/resource-owner code with PF-003.

Preserve rendering/state output. Dedicated branch → PR → required checks → merge only after checks pass → verify `master` → update ledger/RAG → close only on acceptance.

## Acceptance criteria

- Recyclable renderer identity classes and their owners/reset events are documented.
- At least one deterministic stale-reference negative fixture is detected/rejected rather than resolving to unrelated new data.
- Generation/epoch checks are available to PF-003/PF-004/PF-005 without requiring a global heavyweight handle abstraction.
- Normal current rendering has no intentional image/material/light/probe change.
- Debug/diagnostic overhead can be disabled or is demonstrated negligible in non-debug hot paths.
- Required CI passes; PR merged and verified on `master`.

## Verification

Run PF resource allocate/free/reuse and repeated level/resource reset fixtures; intentionally hold a stale debug reference through reuse/reset and assert detection; compare baseline material/light/probe state and image evidence.

## Expected artifacts

- lifetime/generation contract implementation;
- stale-reference diagnostics/tests;
- explicit reset/epoch hooks;
- updated `rag/02-RENDERER-IDENTITY-LIFETIME.md`;
- PF evidence/ledger entry.

## Blocking / stopping conditions

Stop if a proposed generic handle model materially increases hot-path indirection/memory without evidence, if subsystem ownership cannot be identified precisely, or if introducing generations changes valid resource resolution rather than only detecting stale use. Record the narrower design needed and block dependents instead of forcing a universal abstraction.
