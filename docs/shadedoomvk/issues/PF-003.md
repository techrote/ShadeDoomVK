# PF-003 — Bindless descriptor capacity, reservation and reuse hardening

## Objective

Harden the inherited bindless descriptor allocator so capacity respects actual Vulkan limits, fixed/lightmap/probe reservations cannot overlap dynamic allocations, existing free-bucket reuse is validated, and stale slot reuse is covered by PF-002 lifetime/generation checks.

## Scope / required work

- Inspect baseline `VkDescriptorSetManager` allocation/free/reservation arithmetic and every caller that owns long-lived bindless indices.
- Adapt the useful device-aware/configurable-capacity concept from `jalovisko/VkDoom@033a3c5cb35c82708e4eeb3619373c33ddc40b75`, with exact provenance/licence handling.
- Preserve and test the baseline allocation-size free-bucket reuse rather than reimplementing it as if absent.
- Define runtime capacity from requested setting and relevant physical-device descriptor limits; report effective limit and limiting capability.
- Make fixed resources, lightmap/probe-page reservations and dynamic allocation ranges explicit and bounds-checked. Validate the two-descriptor-per-lightmap-page/probe-map coupling and on-demand two-slot environment probe pairs.
- Integrate PF-002 generation/epoch validation at recyclable long-lived bindings where applicable.
- Add high-water/current/free/reuse/failure diagnostics and deterministic near-capacity/exhaustion tests.
- Fail safely/clearly without the MAD-VKDoom global flush behavior that can leave stale LevelMesh indices.

## Non-goals

- Do not redesign semantic materials (PF-008/SDVK-005).
- Do not build rich-material stress qualification owned by SDVK-004.
- Do not increase limits beyond device capability to make tests pass.
- Do not add a global texture flush that invalidates live references.

## Confirmed implementation finding

The baseline reservation defect is now source-proven: dynamic allocation began at descriptor `3 + 128 = 131`, but each lightmap page writes **two** descriptors (light + probe). More than 64 lightmap pages could therefore overlap live dynamic material/probe allocations. PF-003's contract reserves all 256 lightmap/probe descriptors, so the dynamic range starts at **259**.

Implementation and validation details live in `docs/shadedoomvk/PF-003-BINDLESS-CONTRACT.md`.

## Acceptance criteria

- Effective bindless capacity never exceeds relevant device limits and is reported diagnostically.
- Fixed/lightmap/probe/dynamic regions cannot overlap under tested maximum/page-count cases.
- Existing free-bucket reuse is exercised and PF-002 generation/lifetime checks reject stale reuse.
- Repeated material/probe/lightmap allocate/free cycles do not resolve a stale reference to unrelated data.
- Exhaustion produces a precise controlled error/fallback consistent with the issue contract, not stale-index global flush behavior.
- Baseline output/state remains equivalent outside deliberate diagnostics/error handling.
- Required CI passes; PR merged and verified on `master`.

## Verification

Run PF descriptor stress at ordinary, high-water and near-capacity levels; exercise varying contiguous allocation sizes; create/destroy translated/material variants; create multiple lightmap/probe pages; reset/rebake probes; verify allocation counters/generations and image/state equivalence.

## Blocking / stopping conditions

Stop if the device-limit model cannot be derived safely from available Vulkan limits, if a reservation scheme would require silently reducing active resources, or if lifetime safety requires a broader PF-002 change. Block dependents rather than masking the issue with a flush or arbitrarily huge static limit.
