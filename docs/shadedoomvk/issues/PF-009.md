# PF-009 — Sprite render-surface and orientation-state extraction

## Objective

Extract a canonical renderer-side description of sprite geometry/orientation/mirroring/billboard state from the large inherited sprite path, without yet changing tangent-space lighting, POM, shadow representation or visible output.

## Scope / required work

- Audit `HWSprite::Process`, sprite frame/rotation selection, direct picnum path, face/wall/flat sprite modes, scale/offset/floorclip/bobbing, angle interpolation, mirror flags and portal mirror state.
- Introduce a compact sprite render-surface/orientation state carrying the information later consumers need: selected frame/texture, UV mirror, billboard mode, render position, dimensions/scale, world/render angles, right/up/facing or sufficient basis inputs, portal/mirror handedness and alpha silhouette/material identity.
- Separate state derivation from state consumption enough that normal mapping, light queries and future shadow/POM code can share one meaning instead of re-deriving orientation independently.
- Preserve existing geometry generation/material binding/order and all sprite compatibility behavior.
- Add diagnostics/fixtures for 8/16-way rotations where applicable, mirrored frames, face/wall/flat sprites and mirror/portal views.

## Non-goals

- Do not change normal-map TBN; SDVK-007 owns that.
- Do not add height/POM or new sprite shadows.
- Do not fix the assigned clipping/sky/portal bugs owned by PF-014 unless extraction makes the old code unreachable; preserve reproducers in that case.
- Do not redesign gameplay actor orientation or sprite definitions.

## Dependencies

PF-001.

## Concurrency guidance

May overlap PF-002/PF-004/PF-006/PF-007/PF-011. PF-014/PF-016 and later SDVK-007/012 depend on the contract. Do not run PF-014 concurrently against the same sprite-state code.

Read `AGENTS.md`, PF-001 evidence, `rag/01-RENDERER-EXECUTION-MAP.md`, `rag/07-PORTAL-COORDINATE-SPACES.md`, material RAG and current sprite/model/portal source.

## Autonomous implementation prompt

Complete PF-009 autonomously. Extract existing sprite orientation/render-surface meaning without changing it; add diagnostics and old/new geometry/state equivalence fixtures; keep later tangent/POM/shadow policy out of scope. Dedicated branch → tests/docs → PR → required checks → merge → verify `master` → RAG/ledger → close on acceptance.

## Acceptance criteria

- One documented state/contract supplies orientation/mirror/billboard inputs for later sprite-light/shadow consumers.
- Existing sprite frame selection, geometry, UVs, culling/material state and portal/mirror presentation remain equivalent.
- Diagnostic fixtures cover representative rotations, mirrored frames and sprite types.
- No explicit new TBN/POM/shadow behavior is introduced.
- Required CI passes; PR merged and verified.

## Verification

Compare pre/post sprite vertex/UV/frame/mirror/material state and images for representative actors, face/wall/flat sprites, interpolation, mirror and linked-portal contexts.

## Expected artifacts

Sprite render-surface/orientation structure/API; equivalence diagnostics/tests; updated portal/material/execution RAG; evidence/ledger entry.

## Blocking / stopping conditions

Stop if extraction requires redefining Doom sprite rotation/mirroring semantics, or if old/new geometry cannot be shown equivalent. Keep compatibility branches explicit rather than normalizing them away speculatively.
