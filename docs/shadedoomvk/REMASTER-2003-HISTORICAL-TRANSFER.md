## Migration procedure and closure gate

1. Preserve links to original issue, code PR, sources and any **material** root-cause reproducers; leave old results immutable and labelled with their original test methods.
2. Create the new campaign tracker issues with actual scope, non-goals, measurable acceptance and link to this ledger and the engineering policy.
3. Add concise transfer comments to historical issues once targets exist. Nothing in this process awards a PASS to old failure records.
4. Keep all founding issues open until the owner **separately approves** exact closures; close only with a comment specifying “superseded by ...; not technically completed under original acceptance”.
5. Any future archival cleanup must keep the first serious GPU incident, root-cause repairs and unresolved boundaries accessible without redistributing copyrighted game content or private hardware dumps.

**Non-goal:** re-implementing every historical “should compare” or test harness just because it appears in the founding programme. The new programme is product-led and explicitly risk-based.
